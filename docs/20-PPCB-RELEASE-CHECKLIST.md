# PPCB 一页发布检查卡

适用：现有 `palmpay-design-hub-builder` 的普通代码更新。2026-09-20 更新。

原则：沿用成功构建方式；不重复导入数据；只发一次测试候选；验收后晋级同一镜像。追求减少失败重做的总成本，不以删掉必要验证换取速度。

## 每次执行

1. **定范围**：按 AGENTS 阅读 00/05/06/15 和本卡；确认独立目录、`codex/ppcb-deployment`、新仓库 origin，核对 staged/unstaged/untracked 文件。记录相对上次实际发布的累积差异，不只看最后一个 commit。没有代码改动就不重建；业务内容通过应用更新。
2. **本地一次验证**：按变更执行类型检查、Lint、相关测试和构建。PPCB 候选需确认 API 与 testing/production 两套 Web 构建、打包依赖和迁移文件完整；同一候选已验证的未变部分复用记录，不因写文档而重复构建。启动/迁移/依赖/打包有变更时，加跑真实本地数据库与组装产物冷启动、重启；必要检查不通过就不上传。
3. **冻结一次**：提交验证过的源码，运行 `pnpm ppcb:package`，保留仓库外 ZIP、commit、字节数及 SHA-256。脚本不检查未跟踪文件或全面敏感内容，须人工检查实际包清单：根目录正确、迁移 SQL 齐全、无 `.env*`/密钥/备份/依赖缓存。33 个 `project-pages/` 静态页面不进 PPCB 包。
4. **实时预检**：确认 PPCB 连接、身份、平台健康、应用和环境状态；核对最新受管源码，取得本次 `baseRevision`。同一 ZIP 上传一次、合并校验、预检。大于 5 MB 用平台约定分片，先验证本地分片连续性、总长度与整包哈希。不要复用历史 revision 或换包后复用预检。
5. **一次测试发布**：沿用 Node 24/OpenSSL、成功的单阶段 Dockerfile、8080、`/healthz`、受管数据库和既有授权。记录确切 build/operation/release；确认终态、实例与健康，再分别用 Owner 和普通 `User` 真实登录。`User` 必须能打开工作台、读取内容、创建内容、编辑本人内容和执行 AI Skill，同时不能获得全量编辑、下架、归档、分析、用户、分类、审计或 AI 管理权限；不能以 Owner 验收代替普通成员验收。继续检查改动功能和受影响文件链路。普通发布日志应没有内容/封面导入；已有组织应输出 `initialized:false`。出现问题先冻结会扩大影响的同一步骤，保留现场并只读诊断，给出最小处理方案后与用户沟通；不因一般异常自行终止整次发布。
6. **一次生产晋级**：先列明测试结果、未测项、生产影响及可行回退措施，取得覆盖该候选的生产确认，再晋级同一测试镜像；不重新打包、上传、构建或复制测试数据库。复核生产健康、登录与关键功能，更新 05 和发布记录。

## 数据与例外

- **无数据库变化**：保留迁移账本检查；已完成 SQL 不重复执行。已有组织不 seed，不导入 48 条历史内容，不上传 5 张历史封面，不重置业务编辑或角色授权。
- **权限配置变化**：先核对 `authMode` 和平台角色权限，再核对应用内角色权限；两层取交集。权限定义更新会直接作用于测试和生产运行时，不因“没有代码变化”而省略双角色验收，也不为纯配置修改重建镜像。
- **全新环境**：带锁事务只初始化一次基础配置，内容为空。历史迁移、缺失基础配置修复、结构/权限/文件协议变化须查 [完整规范](19-PPCB-RELEASE-STANDARD.md) 对应章节并制定专项验证，不混入普通发布。
- **回退边界**：当前线上旧镜像仍会启动导入；它不是数据安全的默认回退版本。首次生产切换前明确备份和恢复措施，后续保留验证过的不自动导入版本。镜像回退不恢复数据库或文件。
- **当前导航限制**：33 个 GitHub Pages 项目的“返回项目库”固定指向 PPCB 生产。测试点击后会跨环境；返回后不得继续测试写操作。若本次验收要求留在测试环境，则先单独修复并部署静态页返回逻辑，不能报为通过。
- **问题处理规则**：预检阻断、revision 冲突或明确失败时，不重复同一副作用动作，也不跳过门禁；先保留证据、只读诊断并向用户给出处理方案。已获授权范围内、问题修复后的后续步骤可继续；需要终止整次发布时先取得用户确认。平台 Issue/FAQ 仍须先展示脱敏内容并确认。

本地通过不代表平台已发布，也不能保证平台镜像仓库、网络和构建器始终可用。完整历史、异常门槛与记录模板见 [19](19-PPCB-RELEASE-STANDARD.md)。
