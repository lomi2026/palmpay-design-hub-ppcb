# PalmPay Design Hub · 体验审视与双方案交付

日期：2026-09-13。审视对象为本机实际运行的正式前端、API 与现有组织数据。截图为本轮浏览器实测，不是静态效果图。

## 先看两个最终方案

| 方案 | 入口 | 设计判断 |
|---|---|---|
| A · 精修版 | [进入工作台](http://127.0.0.1:3000/workspace) · [发布内容](http://127.0.0.1:3000/workspace/submit) | 延续克制的黑白基调，降低迁移成本。优先解决排版、内容结构、动作层级和一致性。 |
| B · Studio | [全新首页](http://127.0.0.1:3002/) · [进入工作台](http://127.0.0.1:3002/workspace) · [发布内容](http://127.0.0.1:3002/workspace/submit) | 灰紫底、白色柔和卡片、深色重点区和少量青柠强调。更像设计师每天愿意打开的工作空间。 |

建议先体验 B 的首页 → 工作台 → AI 工具或 Skill → 详情，再创建一份草稿体验完整流程。A 适合稳妥演进，B 更适合作为下一阶段视觉方向。两者共享真实业务数据与权限，使用的是同一套发布和阅读组件；在任意方案发布或删除内容，另一方案也会反映真实结果。

## 体验结论

原平台已经具备内容沉淀、发现、复用、个人创作和组织管理的基础能力。主要障碍集中在“我要填什么”“这些信息最终出现在哪里”“当前动作到底保存、发布还是修改正式内容”三个问题，而非缺少更多装饰。

本轮把发布体验拆成轻量起草、分章节完善、同结构预览、发布四步。详情页首先回答“这是什么、谁维护、怎么使用”，接着展示适用范围、执行方法、例子和证据。常用动作保持在标题附近，低频管理动作进入更多菜单。未填写的信息不会用模拟数据补齐。历史 Skill 的耗时/复杂度不再冒充执行步骤；缺少的关键内容会明确提示待作者补充。

## 参考图的设计特色与取舍

第一张参考图的优点是灰紫底上的层叠白色卡片、温和的大圆角、充足留白和低对比边界；它适合高频工作台。第二张的优点是黑色重点模块、明确的数字层级和少量高亮青柠色；它适合突出主要动作。

B 以第一张的柔和空间为基础，吸收第二张的黑色重点区与动作强调。没有照搬银行卡、聊天窗或虚构数据。首页的视觉卡片分别链接到真正的工具、方法和团队资源；工作台展示实际可见内容及自己的草稿。

### 保留的业务边界

- 草稿保存不等于发布；内容未完整时可以保存，点击发布才执行必填校验。
- 发布经过服务端完整度和编辑权限校验，立即进入既有可见范围，不存在新增审核审批步骤。
- 已发布内容的编辑仍通过新草稿版本完成，未发布修改不会提前替换正式内容。
- AI 结果的人工复核、项目验证阶段是知识内容，不是被取消的平台审批功能。
- 分类标签停用后不再提供新选择，已有历史关联可保留或移除。
- 无封面显示灰色占位；封面限 PNG/JPG/WebP、5 MB；普通附件限 100 MB。
- 关联选择仅展示当前账号可访问的正式内容；不可访问的旧关联不泄露标题。
- 登录、组织隔离、角色权限、归属、版本与审计规则继续生效。

## 核心发现与已经落实的优化

| 优先级 | 原问题 | 使用者影响 | 已落实 |
|---|---|---|---|
| 高 | 起草时一次要求所有专业字段 | 很难开始，长页面增加漏填 | 起草与完善分离，专业字段分章节，提供进度 |
| 高 | 编辑、预览、详情分别定义字段 | 填了却不展示，或展示格式不同 | 同一字段结构驱动编辑和两种阅读界面 |
| 高 | 历史内容的字段只在投影表中 | 重新编辑时出现空表单 | 从已发布详情补齐历史草稿的可读字段 |
| 高 | 保存预览后返回旧路由缓存 | 看起来像内容丢失，可能覆盖新值 | 预览前使草稿路由缓存失效 |
| 高 | 发布/删除后先刷新旧草稿 | 停在无效页面或错误跳转 | 服务端完成动作后直接跳往正确页面 |
| 高 | 详情暴露原始 JSON 与导入元数据 | 内容难读，干扰使用判断 | 提取可读内容，列表、段落、链接分别排版 |
| 中 | 关联字段要求手填编号 | 普通作者难以完成关联 | 可搜索名称选择，详情显示名称链接 |
| 中 | 已收藏内容仍出现收藏按钮 | 无法判断成功，也不能直接取消 | 工作台共享真实收藏状态 |
| 中 | 自定义下拉变化不触发自动保存 | 下拉值可能未保存，进度不更新 | 显式值变化回调接入保存和完整度统计 |
| 中 | 附件宣传上限与传输上限不符 | 大文件上传意外失败 | 传输允许 100 MB 附件，客户端/服务端限制一致 |
| 中 | 连续附件动作反馈相同 | 再次上传后列表可能不刷新 | 每次成功返回独立时间戳并刷新 |
| 中 | 手机隐藏了全局搜索按钮 | 手机用户缺少重要入口 | 增加紧凑搜索图标及可访问弹层 |
| 中 | 标题大、按钮乱、信息散 | 注意力被低频操作分散 | 统一阅读头部、按钮高度、间距和元数据 |
| 中 | 弹层位于主题容器外 | 下拉或对话框主题不一致 | 主题变量覆盖根节点和浮层 |
| 中 | 常规请求缺少等待上限 | 服务异常时可能持续等待 | 服务端常规数据请求增加 15 秒超时 |

## 发布字段与详情的对应方式

通用字段：标题和摘要进入详情头部；团队与负责人进入元信息；分类参与查找；封面进入视觉区；附件进入下载区。本次修改说明属于版本记录，不占据正文。标签保留检索与管理作用，不重新堆满正文。

每一类内容的专业字段由同一份定义驱动表单和阅读页。切换编辑章节不会卸载其他字段，因此保存和发布仍提交完整内容。以下矩阵记录本轮实际实现。

## 统一组件基准

| 项目 | A · 精修版 | B · Studio |
|---|---|---|
| 基调 | 原有黑白与中性色，支持深浅主题 | 灰紫工作背景、白色阅读卡片；深色为暖紫黑 |
| 布局 | 延续现有导航，统一内容宽度与纵向节奏 | 浮动圆角侧栏，新首页和任务导向工作台 |
| 标题 | 工作区一级 32 px，手机 26 px；二级 21 px | 相同可读层级，首页允许更强视觉标题 |
| 卡片 | 常用卡片约 18 px 圆角、轻边界 | 常用卡片约 24 px，大模块 26–28 px |
| 控件 | 输入与筛选以 40 px 为基准；关键动作 44 px | 相同交互尺寸，主要动作局部胶囊化 |
| 正文 | 13–14 px，长文 1.9 左右行高 | 相同阅读基准，减少强边框干扰 |
| 图标 | 统一 Lucide 线性图标，工作区线宽 1.65 | 同一图标族，少量功能性紫/绿色强调 |
| 交互反馈 | 清晰焦点、处理中、错误与完成状态 | 相同功能反馈与键盘行为 |
| 移动端 | 单列正文、双列基础元信息、可滚动章节导航 | 相同响应式规则，类型选项改为紧凑双列 |
