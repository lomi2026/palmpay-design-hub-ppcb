日期：2026-09-04。范围：用户确认的分类/标签选择、停用规则、版本发布同步、真实关联数量与查看入口。不包含批量迁移或标签合并。

## 行为与 API

- `GET /api/content-drafts/taxonomy`：登录且具有 `content.read` 权限的用户，读取当前组织启用的分类/标签。分类包含适用内容类型。
- `POST /api/content-drafts`、`PATCH /api/content-drafts/:id`：接受 `categoryId` 与 `tagIds`（最多 50 个、不重复的 UUID）。PATCH 省略字段表示保留；`categoryId: null` / `tagIds: []` 表示清除。
- 创建和保存会校验组织、启用状态和分类适用类型。只有该草稿原有的停用关联可以保留。直接伪造 `body.taxonomy` 不能绕过验证。
- `GET /api/content-drafts/:id`：继续校验作者或获授权编辑者身份，增加 `taxonomy` 和 `taxonomyOptions`，后者包含已选择的停用项，供编辑界面标记历史关联。
- 正式目录返回分类/标签状态；普通筛选仅提供启用项，历史内容与其标签展示保留。显式历史筛选链接保持可用，权限规则不变。
- 管理分类/标签的 `usageCount` 改为实际当前关联数；`GET /api/admin/contents?categoryId=...` / `?tagId=...` 支持受 `content.edit_all` 保护的分页查看。排除软删除内容，包含未发布内容的当前关联，不包含历史版本或已发布内容尚未发布的修改。
- 不增加数据库实体或迁移；通过现有版本 JSON 快照与关系表完成。停用只控制新增选择，不回写或删除历史版本。
